**Subject:** Makuo Ifedike portfolio (recorded as Ifedike Victor until 2026-10-27) — `ifedike_makuo` workspace  
**Date:** 2026-10-26  
**Status:** Approved by owner on 2026-10-26. Implementation not started; this agent does not build.  
**Companions:** `decisions.md`, `engagement-plan.md`, `project-facts.md`, `architect-handoff.md`, `plan.md`

**Bottom line.** Build one pure Next.js app, not a Next.js shell around a static page. Keep the portfolio to one page with sections. Project cards open large case-study modals; the only link inside a modal goes to the live project. The contact form is a popup, opened only from the bubble’s **Talk** action or the exit-intent modal. ## 2. Product and core problem

**What it is.** A personal portfolio for Makuo Ifedike, positioned as “I build and fix software for small businesses.” The current visible page is a single long Andle-template page: hero, client strip, about, why-choose cards, counters, work tabs, milestones, and a contact footer.

**Who it is for.** Small-business owners and operators who need a marketing site, a web app, or help fixing a slow or half-built system. Not recruiters, peers, or template buyers.

**What it must do.** Move a skeptical owner from “who is this?” to “this person can handle my problem” to “I’ll start a conversation.” The job is a qualified inquiry, not a template showcase.

### Current state at a glance

| Layer | What exists today | Status |
|---|---|---|
| **1. UI** | Andle Bootstrap 5 template; six icon systems; stock Unsplash imagery; placeholder service copy; dead nav links; `noindex`; template credit | **At risk** |
| **2. Data** | Content hardcoded in HTML and generated by a one-shot Python script; 16 project cards for four projects; hardcoded counters; no structured records, inquiry model, or analytics events | **Missing** |
| **3. Business logic** | Nine touchpoints; no qualification, capture, or follow-up; “chat” routes every answer to an anchor; prompts can stack | **Partial / facade** |
| **4. Functionality** | Hero carousel, non-filtering work tabs, project carousels, counters, milestones, `mailto:` contact; no form, no case-study modal, no SEO basics | **Partial** |
| **5. UX** | Long single page; weak proof; email-only CTA; prompts can overlap on mobile; no persistent hire action | **At risk** |
| **6. System model** | Next.js shell redirects to static HTML; metadata says “Whitefire”; unused dependency stack; non-reproducible content build; no git/CI/analytics/monitoring | **Split** |

### The five problems that matter most

1. **Trust gap.** Placeholder copy, stock “client” photos, a stock portrait, dead links, and a template credit sit on a site whose promise is craft.
2. **Split-brain architecture.** Next.js metadata, fonts, and dependencies are unused by the static page visitors actually see.
3. **No real inquiry path.** The only conversion is a `mailto:` link; the bubble asks a question it cannot act on.
4. **Content is presentation.** Project cards are duplicated across tabs; counters contradict the work; the build script has absolute paths and cannot run here.
5. **Engagement before proof.** Prompts can appear before the visitor has seen enough to trust the site, and they can overlap.

## 4. The six layers

### 4.1 Layer 1 — UI

**Job.** Make the portfolio look like the work of one careful craftsman: clear hierarchy, one identity, real assets, accessible components, fast rendering.

**Current evidence.**

- Andle Bootstrap 5 template; 427 KB `style.css`; five local icon-font stylesheets plus Font Awesome CDN.
- Google Fonts imported inside `style.css`; the Next.js `next/font` setup is unused by the visible page.
- Stock Unsplash imagery: hero backgrounds, about portrait, “client” carousel, project thumbnails, favicon.
- Three of four “why choose me” cards still contain template copy.
- Dead links: `index.html`, `projects.html`, `project-details.html`, `blog.html`, `blog-details.html`, `contact.html`; social icons are `#`.
- `<meta name="robots" content="noindex, follow" />`; Next metadata says “Whitefire”.
- Footer says “Built on the Andle template”.
- Engagement dialogs do not manage focus; reduced motion is not handled.

**Target.**

- One visual system: two typefaces maximum, one icon set, a small color/spacing scale, consistent cards and buttons.
- Keep the dark Andle look; no redesign.
- Real project screenshots; the owner’s final portrait (black background, supplied at build time); replace the stock client strip with a **My Stack** grid, not a client-logo strip.
- **My Stack:** static 6×2 grid on desktop, 4 columns tablet, 2 mobile; 28 px monochrome marks with visible labels; no marquee. Source marks from Simple Icons (white SVGs) or official brand kits, download and self-host in `public/logos/`; do not hotlink. Playwright is not in Simple Icons — use the official mark recoloured to white, or substitute Vitest.
- No placeholder copy; every link resolves; one identity across page, metadata, footer, and socials.
- Accessible: semantic headings, focus states, contrast, alt text, 44 px targets, reduced motion.
- Performance budget: mobile LCP under 2.5 s; one icon system; compressed images; no hotlinked stock.

**Actions.**

- **P0 — truth pass.** Remove placeholder copy, replace the stock client strip with the **My Stack** grid, remove the stock portrait, fix dead links and the template credit; confirm `noindex` intent; unify identity.
- **P1 — consolidate the stack.** One icon system; remove duplicate stylesheets; self-host/subset fonts; responsive WebP/AVIF; focus-visible and reduced-motion styles.
- **P2 — design tokens.** A small component set; keep the Andle look but make it deliberate.

**Acceptance.** No fake proof; no dead links; responsive; WCAG AA; LCP under 2.5 s.

### 4.3 Layer 3 — Business logic

**Job.** Encode the rules that turn attention into a qualified conversation: what the form asks, when it opens, when prompts appear, what counts as qualified, and what happens after submission.

**Current evidence.**

- Nine touchpoints: first-time bubble (3s in the current code), returning variant, time-of-day greeting, 50% scroll banner, 45s idle panel, exit-intent modal, footer confetti/toast, card tooltip, referrer-aware opener.
- Bubble: “are you here for a marketing site, a web app, or fixing something that’s broken?” All answers are anchor links.
- No contact form, no booking, no spam handling, no auto-response, no CRM, no qualification definition.
- Prompts are not suppressed against each other. A visitor can receive the bubble, scroll banner, idle panel, and exit modal in one session; fixed elements can overlap on mobile.
- Persistent state: visit count and per-session flags in `localStorage`/`sessionStorage`. Nothing measured.

**Target.**

- **One conversion path:** popup form, opened only from bubble **Talk** or exit modal CTA.
- **Fields:** name, email, need type (marketing site / web app / fix), budget range, timeline, message; optional project link.
- **Qualification rubric:** need type, budget, timeline, decision-maker. Disqualify spam, recruiters, students, vendors.
- **Routing:** Google Sheet record; email backup with `[PORTFOLIO] New inquiry`; WhatsApp second alert; auto-reply; manual follow-up within one business day.
- **Engagement policy:** all nine kept; first bubble 8s; one prompt at a time; 20s cooldown; no session cap; form open suppresses prompts; submit ends prompts for the session.
- **No form section:** the page has no inline form.
- **Measurement:** events for prompt shown, CTA click, form open, form submit, form close.

**Actions.**

- **P0 — define qualified inquiry and write the form.** Fields, validation, consent, success/error states.
- **P0 — build routing and alerts.** Google Sheet, email, WhatsApp, auto-reply. Test the flow end to end.
- **P1 — implement the queue.** Shared active-prompt state, 20s cooldown, priority, no stacking.
- **P1 — wire the nine touchpoints.** First bubble 8s; returning/referrer variants; banner; idle; exit; footer; tooltip.
- **P2 — scoring.** Use need, budget, timeline to prioritize; review monthly.

**Acceptance.** No two prompts visible at once; form opens only on click; submission reaches Sheet, email, and WhatsApp; no form section; keyboard-usable.

## 6. Success metric

**Qualified inquiry rate** = qualified inquiries ÷ unique visitors, measured monthly.

**Qualified inquiry:** a small-business owner or decision-maker with a concrete project — marketing site, web app, or fix — a timeline, and willingness to discuss budget. Excludes spam, recruiters, students, vendors.

**How to measure.**

1. Analytics: unique visitors, source, `project_view`, `cta_click`, `inquiry_start`, `inquiry_submit`, `outbound_project_click`.
2. Inquiry log: every submission tagged with source, need, budget, timeline, status (new / qualified / replied / won / lost).
3. Manual qualification within one business day.

**Baseline first.** Instrument, then set a 30-day baseline; do not invent a target before it exists. After 30 days, set a 90-day target and review monthly.

**Guardrails.** Reply within one business day. Mobile LCP under 2.5 s. Form completion at least 60% of started forms. No spam increase. No organic drop after removing `noindex` and adding SEO basics.

**Leading indicator.** Project view → CTA click. If they view but do not click, proof or CTA is the problem. If they click but do not submit, the form is the problem.

## 7. Risks and what not to build

| Risk | Why it matters | Mitigation |
|---|---|---|
| Placeholder content and fake proof | A craft portfolio cannot contain template residue. | Truth pass; remove unverifiable claims. |
| Split-brain architecture | Two sources of truth; unused metadata/dependencies. | Pure Next.js; delete the static page and redirect. |
| Engagement overload | Prompts can stack and feel desperate. | One prompt at a time; 20s cooldown; all nine queued. |
| No real inquiry path | Email-only loses visitors. | Popup form; Sheet + email + WhatsApp. |
| Content/presentation coupling | Copy changes become code changes. | Structured content; deterministic build. |
| Unverified claims | Counters, Lighthouse claims, fake client logos damage trust. | Verify or remove; derive from data. |
| `noindex` left on | Portfolio invisible to search. | Confirm intent; remove when public; sitemap/robots. |
| Unused dependencies | Security/maintenance surface. | Remove after verification. |
| No analytics | No baseline or learning. | Instrument before launch. |
| Fake urgency/confetti | Reads unserious. | Keep confetti only as planned; no fake urgency. |

**Do not build now:** blog, AI chatbot, client portal/auth/dashboard, CMS/database for four projects, more engagement touchpoints, full visual redesign before truth pass, multi-language/dark mode.
